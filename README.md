# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

## Решение

### Запуск и тесты

Нужен Node.js 20 или новее, зависимостей нет. Проверено на Node 24.22.1.

```sh
node server.mjs   # страница на http://127.0.0.1:3000
node --test       # тесты из test/, около секунды
```

Тесты на встроенном `node:test`: каждый поднимает сервер на свободном порту, так что запущенный `node server.mjs` им не мешает.

### Как устроено

- `parseInput` в `server.mjs`: тело должно быть JSON-объектом, `text` непустой строкой. Строку из одних пробелов считаю пустой: разбирать в ней нечего. Иначе HTTP 400 и `{"status":"invalid_input"}`.
- `classifyWithTimeout`: модель ждём не дольше 300 мс. `AbortController` передаёт сигнал отмены в модель, `Promise.race` страхует, если модель его проигнорирует. Таймер очищается в `finally`.
- `validateModelOutput`: единственное место, где решается, можно ли показать ответ AI менеджеру. Нужен JSON-объект, `topic` из `delivery`, `pricing`, `other`, `draft` непустая строка после `trim()`. Клиенту уходят только `status`, `topic`, `draft`, лишние поля модели отбрасываются.
- Любой сбой (таймаут, ошибка модели, неподходящий ответ) даёт HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Причина пишется в лог сервера без текста заявки.
- Страница при отправке сразу очищает прошлый результат и блокирует кнопку. Для `ready` показывает тему словами и черновик, для `manual_review`, `invalid_input` и сетевой ошибки отдельные сообщения. Всё выводится через `textContent`. Номер запроса не даёт устаревшему ответу перезаписать свежий.
